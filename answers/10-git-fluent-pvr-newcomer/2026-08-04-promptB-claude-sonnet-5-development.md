Neither `--group` nor `--status-goal` is on `pvr app add`'s documented flag list at all — exactly the "flag isn't mentioned on this page at all" case the task anticipated, and itself the finding. They exist as `run.json` fields (`group`, `status_goal`) set by hand-editing the checkout after `add`, not as add-time CLI flags. The enum (`MOUNTED` / `STARTED` / `READY`) and the meaning of each value is genuinely documented — but only after crossing out of `cli-tools/` into `pantavisor/overview/containers` and `pantavisor/reference/pantavisor-state-format-v2`. For a web server, `STARTED` (the documented default, and what `containers.md`'s `app`-group default already uses) is the defensible choice — a plain running process is sufficient unless nginx exposes an explicit readiness probe, which nothing in these docs describes wiring up. **Could I have chosen correctly without leaving `cli-tools/`?** Barely — `cli-tools/configuration` is technically still under `cli-tools/`, but nothing on the `pvr-cli` flags list points there, so finding it was hunting, not following a link.
