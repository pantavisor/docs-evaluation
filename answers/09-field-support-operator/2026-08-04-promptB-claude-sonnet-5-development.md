## Runbook I wish I had (from what the docs gave me)

**1. App down, device up.** `pvcontrol ls` (status/group/status-goal/restart-policy) or `lxc-ls -f` for the docker-ps equivalent → `tail /pv/logs/<revision>/<container>/lxc/console.log` for its logs → `pvcontrol containers restart <name>` to restart it. Found it, but split across two sections (meta-pantavisor Troubleshooting for status/logs, pantavisor/tools/pvcontrol for restart) — runnable once assembled, not from Troubleshooting alone.

**2. Unreachable, serial only.** Connect at 115200 8N1, press Enter for the debug shell, then `lxc-ls -f` / `pvcontrol ls` / `tail -f /pv/logs/<revision>/pantavisor/pantavisor.log`. Found and runnable immediately. What "healthy" looks like on the console: not found (S1 above) — I'd be guessing whether what I'm seeing is normal.

**3. Last update broke it.** `pvcontrol devmeta ls` (current `pantavisor.revision`) or the pvtx web UI's Home page (revision number + a dropdown listing `Rev 0`, `Rev 1`, … with a Run button) shows current and prior revisions, entirely locally, no cloud needed — this is the one clean answer of the five, no guessing, and it's a point-and-click UI rather than CLI syntax I'd have to get exactly right at 2am. The CLI equivalent (`pvcontrol cmd run`) has the `locals/` ambiguity noted above.

**4. Disk full.** `pvcontrol storage gc` reclaims space; the running and latest-good revision are protected automatically. Found, but only via a detour into runtime architecture docs (S2 above), and manual-deletion safety is unstated (S3 above).

**5. What's on this device, for Slack.** `pvcontrol buildinfo` + `pvcontrol devmeta ls` (arch, revision, mode, interfaces, sysinfo) + `pvcontrol containers ls`, or one visit to the pvtx web UI's Stats & Config page for RAM/swap/disk/device-meta in one view. Found and runnable, though it's several commands stitched together rather than one — no single "dump everything" command exists on the site.
